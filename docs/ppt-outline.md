# Nodal 项目汇报 PPT 大纲

> 建议 12 页，15–20 分钟；面向评审/投资/技术分享。
> 每页只讲一个判断，图优先于文字；演示页必须真机操作，不放静态假图。

## 1. 封面

- 标题：Nodal —— 思维不再是一条直线
- 副标题：无限画布式 AI 思维推演引擎
- 底部：全栈独立开发 / 2026

## 2. 一个真实的问题

- 传统 AI 对话是线性的：分支被覆盖、结论不可回溯；
- 用一张「对话越滚越长、旧分支消失」的对比图；
- 一句话结论：**我们缺的不是更强模型，而是承载思考的结构**。

## 3. 产品主张

- 一张画布 = 一张可生长的思维图谱；
- 节点承载命题/证据/代码/公式，边承载关系；
- 三种核心动作：**推演、分叉、评审**；
- 展示产品主视觉（深色画布 + 正反分支）。

## 4. 四个关系，构成论证骨架

| 关系 | 含义 | 颜色 |
|---|---|---|
| 推导自 | 从前提得到结论 | 主色 `#4060FF` |
| 反例质疑 | 找出反例/漏洞 | `#ff6b6b` |
| 补充佐证 | 增加证据 | `#36c9a5` |
| 并行假设 | 同时探索多个可能 | `#ffc857` |

- 现场展示：选中节点 → 推演 → 新分支落到空闲位置。

## 5. 核心体验：AI 只增不改

- 用户已有判断是「资产」，不能被模型覆盖；
- 服务端硬约束：AI 只能新增 node/edge，删除/修改直接丢弃并计入 `skipped`；
- SSE 流式返回，前端逐节点渲染，3 秒内看到第一个新节点；
- 展示 `start → node → edge → done` 事件流截图。

## 6. 从问题到结论：一条可回溯的链

- Demo1：AI 著作权辩论推演；
- 核心命题 → 支持方/反例 → 佐证/并行假设 → 结论；
- 演示：点结论，沿边回溯到证据；Fork 成自己的版本继续推演。

## 7. 多方案对比：工程决策场景

- Demo2：缓存穿透方案对比；
- 布隆过滤器 vs 空值缓存，两个 Python 代码节点并排；
- 佐证/反例挂在各自方案上，最后收敛为组合策略；
- 强调：代码节点可直接运行（REPL，受隔离能力约束）。

## 8. 知识库与 RAG：让推演有私有依据

- 上传 PDF/DOCX/MD → 切片 → Embedding → pgvector；
- 画布「临时挂载」，只有挂载文件参与召回；
- 展示 sources 事件：文件名、片段序号、相似度；
- 边界：挂载不持久化，重启需重新挂载。

## 9. 技术架构

```text
React 18 + TS + Vite + ReactFlow + Monaco + KaTeX + Tailwind v4
                         │ HTTP / SSE / WS
Gin + GORM + JWT + AES-256-GCM
        │                    │
PostgreSQL 16 + pgvector   REPL 沙箱（unshare + PTY / Firecracker）
```

- 分层：handler / service / model / middleware；
- 统一响应信封与分段错误码；
- 前端按模块拆 service/type，画布 chunk 懒加载。

## 10. 工程质量

- 13 个模块分批交付，每模块独立分支 + `--no-ff` 合并；
- 后端 `go vet` / `go test`，前端 `typecheck` / `build` 纳入 CI；
- 真机联调：注册→Demo→编辑→推演→撤销→分享→Fork；
- 已知边界公开：Docker 未真机验证、分享只读页占位、Redis 未接入。

## 11. 数据与反馈（上线后）

- 北极星：7 日内产生 ≥3 个分支的画布数；
- 漏斗：注册 → 打开 Demo → 首次推演 → 保存 → 分享/Fork；
- 质量：推演首帧时延、失败率、平均新增节点数；
- 用户访谈：咨询/研发/教学内容三类场景各 5 人。

## 12. 下一步

- 短期：分享只读页、画布 `content_json` 单字段、容器化部署验证；
- 中期：多人协同、模板市场、Agent 编排；
- 长期：团队知识图谱、企业私有部署、REPL 独立沙箱池；
- 结尾回到 Slogan：**思维不再是一条直线**。
