## 1. 产品目标

### 1.1 一句话定位

Nodal 是一个**无限画布式 AI 思维推演引擎**：把"和 AI 对话"变成"在一张无限画布上摆开思路、分叉推演、多智能体协作"。

### 1.2 要解决的问题

现有 AI 工具把思考压成一条线：

| 问题 | 具体表现 | 后果 |
|---|---|---|
| 线性上下文 | 思路只能沿着时间轴往下走 | 想换假设，历史就没了 |
| 单 Agent 回答 | 一个模型给一个答案 | 没有反例、没有校验、错了没人挑 |
| 记忆不可控 | 历史对话与旧文档自动混入 | 前提变了 AI 不知道，结论不可信 |

### 1.3 目标与不做什么

**做**：把思考过程结构化、可回溯、可复用、可协作。
**不做**：不做通用聊天助手，不做单轮快速问答工具，不做自动替用户决策。

### 1.4 衡量成功的指标

| 指标 | 定义 | 目标（MVP 后 3 个月） |
|---|---|---|
| 首图完成率 | 新建画布后完成 ≥5 个节点 + 2 条连线的会话占比 | ≥ 40% |
| 分支使用率 | 使用过推演分支的画布占比 | ≥ 30% |
| 广场 Fork 率 | 公开画布被 Fork 次数 / 公开画布数 | ≥ 0.5 |
| 7 日留存 | 完成首图的用户 7 日内再次打开 | ≥ 25% |

## 2. 用户画像

| 画像 | 场景 | 核心诉求 | 典型痛点 |
|---|---|---|---|
| **研究者 / 学生** | 文献综述、论文假设推演 | 多假设并行、证据可挂载 | 思路一乱就得重开对话 |
| **产品 / 策略** | 方案对比、竞品推演 | 多路径并排比较、可分享给同事 | 结论散落在聊天记录里，找不到为什么 |
| **开发者** | 多方案技术选型、代码验证 | 代码节点可直接跑、方案可对比 | 聊天框给出的代码还得自己复制去跑 |
| **创作者** | 选题发散、脚本结构 | 发散要快、收拢要准 | 发散完就散成一堆碎片 |

## 3. 术语表

| 术语 | 定义 |
|---|---|
| **Canvas** | 一张无限画布，是一个完整项目的思考空间 |
| **Node** | 画布上的一个思考单元，类型见 §5.1 |
| **Edge** | 两个节点之间的有向关系连线，带关系标签 |
| **Agent** | 具备固定角色的 AI 执行单元，可独立选模型 |
| **Knowledge Base** | 用户私有的文件集合，可切片检索 |

| **Fork** | 基于某节点或整张画布复制出一条新分支，不影响原图 |
| **Square** | 公共广场，展示已公开的画布 |

## 5. 交互与规则

### 5.1 节点类型

| 类型 | 内容 | 编辑器 | 特殊能力 |
|---|---|---|---|
| `text` | 富文本 / Markdown | 内联编辑 | 可被 Agent 引用为上下文 |
| `code` | 代码片段 | Monaco | 可调用 REPL 沙箱执行 |
| `formula` | LaTeX | KaTeX 实时预览 | 只读渲染 + 可编辑源码 |
| `file` | PDF / TXT | 上传后切片 | 可被检索、可被引用 |
| `image` | PNG / JPG | 上传 / 标注 | 支持被多模态模型读取 |

### 5.2 关系类型（Edge Label）

| 关系 | 语义 | 颜色 |
|---|---|---|
| `derives` 推导自 | B 由 A 推出 | `#4060FF` |
| `refutes` 反例质疑 | B 反驳 A | `#FF6B6B` |
| `supports` 补充佐证 | B 为 A 提供证据 | `#36C9A5` |
| `parallel` 并行假设 | B 与 A 是并列的另一条路 | `#FFC857` |
| `optimizes` 优化分支 | B 是 A 的改进版本 | `#4060FF` 60% |

### 5.3 推演规则

1. **不自动跑**：Agent 只在用户显式触发时执行，禁止后台偷偷生成。
2. **只增不改**：Agent 只能新增节点与连线，不得修改或删除用户已有节点。
3. **可中断**：流式生成过程随时可停止，已生成部分保留。
4. **可回退**：每一轮推演产生一个可回退的节点组。
5. **前提变更**：被引用节点的内容变化后，下游节点标记"前提已变更"，由用户决定是否重推。

### 5.4 上下文隔离

1. 画布之间**默认完全隔离**，A 画布的对话与节点不会进入 B 画布。
2. 知识库必须**手动挂载**才可被召回；挂载是画布级临时状态。
3. 关闭画布自动解除挂载，不持久保存。
4. 每次推演只携带：被选中节点 + 其直接上游节点 + 已挂载知识库召回片段。

## 8. 安全与隔离

1. **REPL 沙箱**：Firecracker microVM / 容器隔离，只允许 Python 与 Shell 片段；禁止外网出站、禁止持久化文件、单会话 30s 超时、内存上限 256MB。
2. **提示注入**：知识库内容作为"数据"注入，与 system prompt 严格分隔，模型输出不得改变系统规则。
3. **API Key**：用户自带 Key 加密存储，仅用于该用户发起的请求。
4. **权限**：画布编辑仅 owner；分享链接按 share_mode 校验；广场内容需过审后公开。
5. **内容安全**：上传文件类型白名单 + 体积上限；生成内容走平台审核。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 画布复杂度劝退新用户 | 首图完成率低 | 预置 Demo 画布 + 引导式首推演 |
| AI 生成质量不稳 | 用户不信任节点内容 | 校验者 Agent 默认参与 + 节点标记来源与置信度 |
| 多 Agent 成本高 | 单次推演费用不可控 | 每 Agent 独立模型 + 消耗看板 + 预算上限 |
| 广场内容质量 | 品牌受损 | 审核 + 优质内容加权 + 举报机制 |
| 沙箱逃逸 | 严重安全事故 | microVM 强隔离 + 出站全禁 + 定期渗透测试 |
